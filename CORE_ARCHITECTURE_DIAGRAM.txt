================================================================================
                      MODULE SCHEMA STRUCTURE
================================================================================

ModuleSchema {
  id: string
  name: { en: string, mm: string }           ← Multilingual
  slug: "students"
  serviceName: "cpms"
  
  formLayout: "studentWizardForm"            ← Controls form display
  formFields: [...]                          ← Form field definitions
  
  dataTableSchema: {                         ← List view config
    columns: [...]
    pagination: {
      isClientSidePaging: true|false        ← Determines fetch strategy
      pageSize: 10
    }
  }
  
  moduleAccessPolicy: {                      ← Access control (server-only)
    accessPolicy: {
      systemAdmin: { operation: { read: true, create: true } },
      user: { operation: { read: true, create: false } }
    }
  }
}

================================================================================
                        DATA FETCH STRATEGIES
================================================================================

STRATEGY 1: CLIENT-SIDE PAGINATION (isClientSidePaging: true)
─────────────────────────────────────────────────────────────

Server (page.tsx):
  getModuleList() ──(10s timeout)──> API
       │
       ▼
  All data loaded + timeout fallback

Client (ModuleDataTableWrapper):
  - Receive full dataset in initialData
  - Handle pagination in browser
  - Filter, sort, search locally


STRATEGY 2: SERVER-SIDE PAGINATION (isClientSidePaging: false)
──────────────────────────────────────────────────────────────

Server (page.tsx):
  Return empty initialData

Client (ModuleDataTableWrapper):
  Routes to ServerSidePaginationWrapper
       │
       ▼
  On page change:
    Fetch from /api/modules/[slug]?page=N
       │
       ▼
  With timeout handling & retry
